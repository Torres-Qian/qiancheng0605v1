## 六、10000 行文件测试

| 指标 | 值 |
|------|-----|
| 文件 | 10000-orders.xlsx |
| 文件大小 | 4.43 MB |
| Multipart 大小 | 4.43 MB |
| HTTP 状态 | **413** (FUNCTION_PAYLOAD_TOO_LARGE) |
| 耗时 | 1521ms |

### 原因分析

Vercel Serverless Function 的请求体限制为 **4.5MB**。10000 行文件 4.43MB 加上 multipart/form-data 编码开销（boundary、headers）后实际传输量超出限制。

### 解决方案

1. **升级 Vercel 套餐**：Pro 套餐支持 50MB payload
2. **前端分片上传**：将 10000 行拆分为 2-3 个文件上传
3. **使用 Vercel Edge Function** 或 **直接上传到对象存储（S3/R2）**
4. **前端 JSZip 压缩**：上传前 gzip 压缩，后端解压

## 九、结论

### 达标项
- ✅ 全链路处理 1000 行仅需 **13.7 秒**，远超 ≤ 60s 目标
- ✅ 20,000 条 SKU 种子数据灌入完成
- ✅ 批量校验（500/批 inArray）和批量写入（500/批 onConflictDoUpdate）
- ✅ 行级错误记录完整（E001-E003 可追踪到行号和字段）
- ✅ 监控看板和 Trace 搜索正常运行
- ✅ 无 500/504 错误，系统稳定

### 未达标项
- ❌ **上传 P95 = 1969ms**，未满足 ≤ 1s 要求
  - 原因：文件预扫描 + 事务内 Outbox 写入为同步操作
  - 优化方向：去除同步预扫描、缩小事务范围、引入缓存预热

### 平台限制
- ⚠ **10000 行文件 HTTP 413**，Vercel 4.5MB payload 限制
  - 10,000 行全链路 ≤ 60s 未能通过实际大文件验证
  - 需要平台配置升级或架构调整

### 已知瓶颈
1. 上传接口的同步预扫描是最大延迟来源
2. Vercel Serverless 冷启动增加首次请求延迟
3. 单批次 1000 行处理约 5-8 秒（含解析+校验+写入）
